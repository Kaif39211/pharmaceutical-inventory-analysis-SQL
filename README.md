## The Problem

In retail and e-commerce, top-line revenue is a vanity metric; bottom-line profit is reality. High sales volume often masks severe profit bleeding, inefficient logistics, and discounting strategies that destroy margins. 

This project is a full-spectrum financial and operational audit designed to look past raw sales numbers. The objective is to surface exactly where revenue is leaking, evaluate supply chain speed, and identify the specific customer segments and regions driving actual commercial value.

## Core SQL — Architecture Highlights

### I. The "Bleeding Products" Revenue Leakage Model (CTE)
*Isolating high-volume products that operate at a net loss to calculate exact loss-margin percentages.*

```sql
WITH Unprofitable_Products AS ( 
    SELECT
        "Product_Name",
        SUM("Sales") AS TOTAL_SALES,
        SUM("Final_Profit_on_Sale") AS TOTAL_PROFIT
    FROM "SALES_DATASET"
    GROUP BY "Product_Name"
    HAVING SUM("Final_Profit_on_Sale") < 0 
       AND SUM("Sales") > 0 
)
SELECT 
    SUM(TOTAL_SALES) AS Bleeding_Products_Total_Sales,
    SUM(TOTAL_PROFIT) AS Bleeding_Profit,
    ROUND((SUM(TOTAL_PROFIT) / SUM(TOTAL_SALES)) * 100, 2) AS loss_margin_percentage
FROM Unprofitable_Products;

```

II. Supply Chain Efficiency Tracker
Calculating the exact average turnaround time from order placement to dispatch.

SELECT 
    "Ship_Mode",
    ROUND(AVG("Ship_Date"::date - "Order_Date"::date), 2) AS Total_Days_To_Ship
FROM "SALES_DATASET"
GROUP BY "Ship_Mode"
ORDER BY Total_Days_To_Ship DESC;



III. Time-Series Monthly Trend Analysis
Chronological mapping of commercial performance.

SELECT 
    DATE_TRUNC('month', "Order_Date"::date)::date AS Order_Month,
    ROUND(SUM("Sales"), 2) AS Total_Sales,
    ROUND(SUM("Final_Profit_on_Sale"), 2) AS Total_Profit
FROM "SALES_DATASET"
GROUP BY DATE_TRUNC('month', "Order_Date"::date)
ORDER BY Order_Month ASC;
